# Credit-scoring

## Описание проекта

Проект посвящён задаче кредитного скоринга. Необходимо предсказать, выйдет ли клиент в серьёзную просрочку по займу в течение 90 дней после его выдачи.

В работе использовалась информация о текущей заявке клиента, а также его предыдущих займах, внешней кредитной истории и транзакциях.

Задача решалась как **бинарная классификация**:

- `0` — клиент не вышел в серьёзную просрочку;
- `1` — клиент вышел в серьёзную просрочку.

## Цель проекта

Построить модель машинного обучения, которая сможет оценивать вероятность возникновения серьёзной просрочки по кредитной заявке и тем самым помогать в оценке кредитного риска клиента.

Основной акцент в работе был сделан на подготовке данных, создании признаков из дополнительной кредитной и транзакционной информации, сравнении нескольких алгоритмов и подборе их гиперпараметров.

## Данные

В проекте использовались пять таблиц:

- `train.csv` — данные о кредитных заявках с известной целевой переменной;
- `test.csv` — заявки, для которых необходимо получить предсказания;
- `previous_loans.csv` — информация о предыдущих займах клиентов;
- `bureau.csv` — внешняя кредитная история клиентов;
- `transactions.csv` — транзакционная история клиентов до даты подачи заявки.

Дополнительные таблицы содержали несколько записей для одного клиента, поэтому перед объединением с основной таблицей информация из них была агрегирована по `client_id`.

## Исследовательский анализ данных

В рамках EDA было сделано:

- заполнены выбросы в каждой таблице по отдельности;
- удалены признаки без смысла;
- закодированы категориальные признаки;
- таблицы объединены в одну с train; 
- удалены признаки с высокой корреляцией;
- обучены модели классификаций.

 ## Модели

Для решения задачи были протестированы несколько алгоритмов:

- Logistic Regression;
- Random Forest;
- XGBoost;
- CatBoost;
- LightGBM.

Модели сравнивались на одинаковой схеме кросс-валидации.

## Валидация

Для оценки качества использовалась **Stratified Cross-Validation**. Стратификация позволила сохранять соотношение классов в тренировочной и валидационной выборках каждого фолда.

В качестве основной метрики использовалась **ROC-AUC**.

ROC-AUC оценивает способность модели правильно ранжировать клиентов по вероятности возникновения серьёзной просрочки.

## Оптимизация гиперпараметров

Для подбора гиперпараметров моделей использовалась библиотека **Optuna**.

Для каждой модели задавался диапазон возможных значений гиперпараметров. Каждый набор параметров оценивался с помощью кросс-валидации по метрике ROC-AUC.

## Результаты

После сравнения и оптимизации моделей были получены следующие результаты:

| Модель | ROC-AUC |
|---|---:|
| Logistic Regression | 0.81459 |
| XGBoost | 0.81837 |
| LightGBM | 0.81632 |
| CatBoost | **0.82140** |

Лучший результат показала модель **CatBoost**.

**Лучший ROC-AUC: 0.82140**

## Финальная модель

В качестве финальной модели был выбран `CatBoostClassifier` с оптимизированными гиперпараметрами.

После выбора модели она была обучена на полном тренировочном наборе `train`.

Затем модель использовалась для получения вероятности класса `1` для объектов из `test`.

Для итогового файла формировались два столбца:

- `application_id` — идентификатор кредитной заявки;
- `target` — предсказанная вероятность серьёзной просрочки.

Результат сохранялся в файл `submission.csv`.

Финальной моделью был выбран **CatBoost**, показавший лучший результат среди протестированных моделей — **ROC-AUC 0.82140**.
